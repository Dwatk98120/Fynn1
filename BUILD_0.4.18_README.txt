HEARLIUM BRANCH 2 - 0.4.18 - PHONEME TIMING AND CAPTURE REPAIR
2026-10-27

Includes the 0.4.17 legacy-checksum and Tk packaging repairs.

Changes
- Add "want" to the independent candidate vocabulary.
- Preserve CTC token IDs, emission start/end frames and nonblank confidence.
  Direct segment ranking derives IPA confidence from actual source tokens.
  Older adjacent-merge suggestions retain their shared confidence and remain
  unverified proposals; they cannot approve pronunciation or learning.
  Use the model output stride for timing; explicitly label fallback estimates.
- Preserve the baseline phoneme sequence/grouping. Add separate split/join
  proposals across short uncertain gaps and disputed predicted delimiters,
  bounded to three fragments. No alternative is automatically selected.
- Add conservative many-to-many timing-overlap groups for phoneme pieces and
  ASR word hypotheses. Existing strict unresolved counts/guards remain intact.
- Add offline PocketSphinx 5.0.4 reference-conditioned word/phone timing.
  In Recording > Evidence, choose Align Confirmed Words after playback and
  enter/confirm exactly what was spoken. Timings use CMU/ARPABET phone labels.
  Reports are separate JSON files under analysis_results/phoneme_alignment_reports.
  This does not approve learning, alter observations, prove pronunciation,
  or identify the speaker. Only PCM16 mono 16kHz WAVs are supported initially.
  Unsupported reference words and incomplete audio fail explicitly.
- New captures save their recording ID, SHA-256 and byte count before Analyze.
  First analysis uses protected original reuse instead of another API WAV copy.
  Historical duplicates remain untouched. No migration rewrites old metadata.
- Tk hidden-window/Evidence-tab and frozen native/model checks gate packaging.

Engine choice
PocketSphinx is used through its native Python binding inside the existing
Windows application. No JVM, Java engine or remote speech service is required.
Reference alignment remains separate from independent CTC recognition.
